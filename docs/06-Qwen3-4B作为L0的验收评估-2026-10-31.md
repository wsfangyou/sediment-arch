# 用 Qwen3-4B 当 L0：能否达到项目验收标准

日期：2026-10-31　｜　被测：`D:/Doubao-works/训练前置/02_基座模型/Qwen3-4B`（4.022B，36 层，hidden 2560，GQA 32:8，tied，vocab 151936）

## 0. 一句话结论

**按项目现行的四项职责判分口径，Qwen3-4B 能过 4/4，而且在最关键的两项（D1 语言、D2 技能承载）上
比现在的 0.83B 自研 L0 明显更强；代价有三个：部署必须 4bit、跨骨干知识包（MSP）依然不成立、
"自研基座"这条研究线终止。**

| 职责 | 判定 | 实测读数 | 与 0.83B L0 对比 |
|---|---|---|---|
| D1 语言能力 | ✅ | 验证 ppl **16.76**（L0 56.9） | **好 3.4 倍** |
| D1 显存预算（6GB 档） | ⚠️ 有条件 | fp16 常驻 7.55 GiB → **超预算 2.4 GB**；NF4 常驻 **2.50 GiB** → 6GB 档余 **2.6 GB** 给 L1 ✅ | L0 fp16 1.54 GiB，本来很宽裕 |
| D2 技能承载 | ✅ **大幅过线** | A_tf **0.994**（≥0.90）/ A_gen **0.960**（≥0.80）/ 裸基座 0.000 | L0 是 0.973 / 0.880，**刚好压线** |
| D2 的 C 门（通用回归） | ✅ **过严格线** | 16.76 → 14.42 = **0.861×**（门限 1.02） | L0 是 1.037×，**没过** |
| D3 MSP 锚点接口（项目口径） | ✅ | 中层标定余弦 **0.983 / 0.985**（判定线 0.60） | L0 0.974 |
| D3 的 ISA 转译（严格口径） | ❌ | b/a **0.029 / 0.043**，机会 0.021 | L0 也是 0.00–0.04，**同病** |
| D4 调度接口 | ✅ | generate 正常、KV 原生 144 KiB/token、解码 200 ms/token | L0 是 3110 ms/32tok（≈97 ms/token） |

> 判分口径说明（避免误读）：项目 `accept_l0.py` 里 D3 的预注册线是「跨骨干标定余弦 ≥0.60 且增益 ≥0.20」，
> 按这条 Qwen3-4B 是 ✅；但更严格的 ISA 转译（把参考骨干训好的键搬过来能不能用）实测只有机会水平。
> **这一条 0.83B 与 4B 完全一样**——所以换 4B 不解决 MSP，也不会让它更糟。

## 2. D2 的两个坑（都是判分口径，不是能力）

### 2.1 第一次读数 A_gen 只有 0.320 —— 是 Qwen3 的思考块

Qwen3 的 chat template 会在答案前插入 ` thinking…<｜end▁of▁thinking｜>`，于是整串 exact match 全灭：

| 口径 | A_gen | 平均输出长度 |
|---|---|---|
| 原始（不过滤） | 0.320 | 27.0 字符 |
| **剥掉思考块** | **0.960** | 8.0 字符 |
| **提示词关思考**（`enable_thinking=False`） | **0.960** | 8.0 字符 |

同一 adapter、同一 50 条 holdout，**只改判分口径，0.32 → 0.96**。
这与项目记录里的 B4（`generate` 不认 `<|im_end|>` 把 A_gen 压低 2.3 倍）是同一类错误：
**自定义/新模型的判分必须显式处理模板，否则量到的是模板而不是能力。**

### 2.2 C 门不仅没过，还倒着走

通用 ppl 从 **16.76 降到 14.42（0.861×）**。原因不是技能"没伤到"通用能力，而是 35% 的 replay 混采
本身就是一次轻量继续预训练。对 0.83B 来说混采只是止损（1.338× → 1.037×），
对 4B 来说容量足够，混采直接变成净收益。**这是换大基座最实惠的一条。**

## 3. 显存账（D1 的 6GB 档）

实测（`bench_qwen_deploy.py`，单卡）：

| 形态 | 权重常驻 | KV@4096 | @ctx4096 前向峰值 | 6GB 档余量给 L1 |
|---|---|---|---|---|
| fp16 | **7.545 GiB** | 0.562 GiB | 13.05 GiB | **−2.4 GB（放不下）** |
| NF4（bnb 4bit + double quant） | **2.503 GiB** | 0.562 GiB | 8.00 GiB | **+2.6 GB** ✅（要求 0.8–1.2） |

> 表里的"前向峰值"含 logits（1×4096×151936×2 = 1.16 GiB）与单层瞬时激活，不是常驻占用；
> 常驻预算 = 权重 + KV + 工作区 ≈ fp16 8.4 GB / NF4 3.4 GB。

**结论：4B 进 6GB 档只有 4bit 一条路**，而且这正好是方案原文的锚点
（"4B 级稠密 Q4_K_M ≈ 2.2–2.8 GB"）—— 换 4B 反而比 0.83B 更贴合方案。
但连带的后果必须写清：**L1 沉积物不能 merge 进 4bit 权重**，只能运行时挂载
（项目已因 C 门结论把 L1 定为"驻留 + 隔离挂载"，所以这条并不冲突，只是从"可选"变成"必须"）。

---

## 4. D3：换成同族骨干也救不了 MSP

上一次的结论（Qwen2.5-3B ↔ 自制 L0）是 b/a 0.00–0.04，机制是"标定误差夹角 ≈ 类间夹角"。
这次用 **同族、同词表、同架构家族** 的一对（Qwen2.5-3B ↔ Qwen3-4B）重测，这是 MSP 最有利的情形：

| 量 | 值 |
|---|---|
| 类间夹角 | 参考 13.2° / 目标 16.3° |
| 标定图保真 | 余弦 **0.983 / 0.985** → 误差夹角 ≈ 10.5–11.6° |
| a（目标骨干本地上限） | 1.000 |
| **b（ISA 转译）** | **0.029 / 0.043** |
| b0（随机投影） | 0.029 / 0.043 |
| 机会 | 0.021 |

**b 与 b0 完全相等 = 转译零信息**。换同族骨干把标定误差从 12–15° 压到 10–11°，但类间夹角只有 13–16°，
信噪比仍然 ≈1，不足以区分类别。**"换 4B 能让 MSP 成立"这个假设被否掉。**

## 5. 三个必须接受的代价

1. **"自研基座"这条线终止。** L0 原本是项目最有辨识度的部分（自制 0.83B、词表对齐、hidden 钩子、KV 记账）。
   换 Qwen3-4B 后这些全部变成"用现成的"，项目退化为"在 Qwen 上做沉积调度"。这不影响 E1/L1/竞价那几条，
   但论文/报告的立意要改写。
2. ~~部署必须 4bit，训练/部署不同精度~~ —— **已补测（2026-10-31 18:26）：量化不掉点。**
   同一 adapter 挂到 NF4 底座上：A_tf **0.9939**、A_gen **0.960**，与 fp16 **逐位相同（差 0.0000）**；
   只有通用 ppl 从 14.42 涨到 15.63（**1.084×**，仍远优于裸基座 16.76）。
   结论：**6GB 档的 4bit 部署可以直接用，不需要为量化重训 QLoRA。**
3. **解码慢，产品指标在本机测不出来。** 200 ms/token（fp16）/ 239 ms/token（NF4），
   远差于这张卡的理论值。结合之前 L0 的 profiler 结论（GPU 8.8ms vs CPU 142ms/forward），
   **瓶颈是这台机器的逐算子调度，不是模型**；方案要的"流畅"必须在目标机（6GB 笔记本）上重测。

## 6. 建议

如果决定换 4B，按这个顺序落地：

| 顺序 | 动作 | 目的 |
|---|---|---|
| 1 | ~~量化后再测 D2~~ | ✅ **已完成，零落差**（见 §5-2） |
| 2 | 用 4B 重跑 **E1 闭环**（≥3 个技能 + 使用统计 + 晋升/回归） | 现在 D2/C 门都过了，闭环终于有合格靶子 |
| 3 | 把 L1 挂载从"merge"改成"运行时 adapter"（4bit 底座上的标准做法） | 部署形态定型 |
| 4 | MSP 那条线**从方案里划掉或改写**：只保留"锚点可标定"，去掉"跨骨干知识包市场" | 已被两组骨干、两种族系否证 |

如果**不改基座**：4B 的这些数据仍然有用——它给出了"如果骨干再大 5 倍，D2 与 C 门能到什么位置"的上界，
也量化了 0.83B 与 4B 在同一个技能上的差距（A_gen 0.880 → 0.960，C 门 1.037× → 0.861×）。
