# 单卡 4B 训练可行性实测 · 2026-10-31

**问题**：这台机器（2× RTX 2080 Ti 22GB 改装版）能不能用**单张卡**训练 4B 模型？

**结论**：**LoRA / QLoRA 可以，全参微调不行。** 卡住的不是权重，是激活。

---

## 0. 一句话答案

| 训练方式 | 单卡 22GB 能否 | 实测最佳配置 | 峰值显存 | 吞吐 |
|---|---|---|---|---|
| 全参微调（fp32 权重 + AdamW） | ❌ 不行 | 1×2048 就撞墙 | 20.67 GiB 时 OOM | — |
| 全参微调（fp16 权重 + 8bit Adam） | ❌ 不行 | 1×2048 就撞墙 | 21.02 GiB 时 OOM | — |
| **LoRA r16（fp16 基座）** | ✅ **可以** | **bs4 × seq2048**（梯度检查点 + 分块 CE） | **18.17 GiB** | **565 tok/s** |
| LoRA r16（保守档） | ✅ 可以 | bs2 × seq2048 | 13.05 GiB | 565 tok/s |
| **QLoRA（NF4 4bit + LoRA）** | ✅ **可以，但 batch 更小** | bs1 × seq2048 | 8.97 GiB | 505 tok/s |

> 换句话说：**4B 的 LoRA 微调在这台机器上是常规操作**，一步 8192 token（bs4×2048）跑 14.5 秒；
> 想练 1000 万 token 大约 **5 小时**。全参微调则**没有任何配置能跑起来**，单卡不可能。

## 2. 怎么测的

没有 4B 模型在本地（只有 Qwen2.5-3B 和 Qwen3.5-9B），所以用**与 Qwen3-4B 完全同构的随机权重模型**：
hidden 2560 / 36 层 / GQA 32:8 / head_dim 128 / vocab 151936 / tied embedding → **4.022B 参数，fp16 权重 7.49 GiB**。
随机权重对显存与速度没有影响（只影响 loss 数值）。

**可信度校验（关键）**：同一套代码换成**真实的 Qwen2.5-3B-Instruct** 跑 bs2×seq2048：
峰值 **10.88 GiB**、905 tok/s。合成 4B 在同配置是 13.05 GiB，两者差值 2.17 GiB，
与权重差（7.49−5.75 = 1.74 GiB）吻合 → **合成模型的数字可以直接外推到真模型**。

脚本：`蒸馏实验/scripts/bench_4b_single_card.py`、`verify_bench_real3b.py`
数据：`蒸馏实验/l0_acceptance/bench_4b/*.json`、`bench_4b*.log`

## 4. 三个值得记住的发现

### 4.1 瓶颈是激活，不是权重（这条最反直觉）

LoRA 的权重只有 7.49 GiB，理论上 bs4 该很轻松，实测却到 18.17 GiB。反推：
**每 1000 token 的激活开销约 1.0–1.3 GiB**，而梯度检查点已经开了
（bs2 开检查点 13.05 GiB，关掉直接 OOM 到 19.96 GiB，说明检查点确实在生效）。

理论上开检查点应该只存"每层输入"≈0.2 GiB/1000 token，实测高 5–6 倍。
我们验过不是 `use_reentrant` 的问题（True/False 都是 13.05 vs 13.09 GiB，完全一样），
怀疑与 PEFT 适配器在每层都要保存输入、以及 sm_75 上 SDPA 退回非 flash 路径有关，**未进一步定位**。

实际影响：**22 GB 卡上 4B 每步的总 token 数上限约 8000–10000**。想更大 batch 只能：
① 装 FlashAttention（本机 Windows + sm75 装不了现成轮子，需自己编译）；
② 缩短 seq；③ 用梯度累积换等效 batch（不影响质量，只影响速度）。

### 4.2 4bit 量化在 22GB 卡上不是决定性因素

QLoRA 只比 fp16 LoRA 省 3.4 GiB（8.97 vs 12.36），却慢了 10%（505 vs 557 tok/s），
而且因为激活占大头，**bs8 一样 OOM**。所以在这台机器上做 4B LoRA，
**首选 fp16 原生权重**，bitsandbytes 4bit 只在"显存差 1–2 GB 就过不去"时才值得用。

### 4.3 全参微调没有任何配置能跑

账单（4.022B 参数）：

| 组成 | fp32+AdamW | fp16+8bit Adam |
|---|---|---|
| 权重 | 14.98 GiB (fp32) | 7.49 GiB (fp16) |
| 梯度 | 14.98 GiB | 7.49 GiB |
| 优化器状态 | 29.97 GiB (m+v fp32) | 7.49 GiB (m+v int8) |
| **小计（不含激活）** | **59.9 GiB** | **22.5 GiB** |

22.5 GiB 已经超过单卡可用的 21.7 GiB，**还没算激活**。实测两条路都在峰值 20.7/21.0 GiB 时撞墙。
要全参只能上双卡 ZeRO-3/FSDP（每卡约 11.3 GiB，宽裕）。

## 5. 推荐配方

### 5.1 单卡 4B LoRA（推荐）

```python
from transformers import AutoModelForCausalLM
from peft import LoraConfig, TaskType, get_peft_model

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-4B", dtype=torch.float16).cuda()
model = get_peft_model(model, LoraConfig(
    task_type=TaskType.CAUSAL_LM, r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules=["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"]))
model.config.use_cache = False
model.gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})
model.enable_input_require_grads()
```

- `per_device_batch_size=4`，`gradient_accumulation_steps=4` → 等效 batch 16（约 32k token/步）
- 学习率 1e-4 ~ 2e-4（LoRA 常规区间），fp16 + GradScaler（**不要用 bf16**）
- **必须做分块交叉熵**：词表 151936，bs4×2048 的 logits 是 2.5 GiB、CE 里再 upcast fp32 变 5 GiB
  单个分配 —— 这是 bs4 一开始 OOM 的直接原因。按 seq 切 512 一块算即可（见 `chunked_ce_loss`）

### 5.2 时间预估（实测 565 tok/s）

| 数据量 | 单卡耗时 |
|---|---|
| 100 万 token | ~30 min |
| 1000 万 token | ~4.9 h |
| 1 亿 token | ~49 h（不建议单卡做） |

### 5.3 想要更快

- **双卡 DDP**：LoRA 是数据并行，每卡显存不变，速度约 1.7×（NVLink P2P 可用，非 WSL）。
- **不要**为了提速开 bf16：Turing 无 bf16 张量核，会掉到慢路径。

## 6. 与本项目直接相关的话

- 现在项目里的 L0 是 0.83B，**换 4B 做技能宿主在单卡上完全可行**（LoRA 档 18 GiB，留 3 GB 余量）。
- 反直觉的一点：**4B 的每 token 训练成本比 0.83B 还低**——4B 实测 1.76 ms/token（565 tok/s），
  L0 实测 2.83 ms/token（2.9 s/步 @bs4×256，= 353 tok/s）。小模型吃不满 2080 Ti，
  所以"更大模型一定更慢"在这里不成立；真正受限的是**单步 token 上限**（4B 约 8000–10000）。
- 若真要把 L0 升到 4B，建议先用 Qwen3-4B 做 LoRA 验证管线（能跑、有基线），再决定要不要自研同尺寸基座
  —— 后者预训练成本按 0.83B 的实测（19B token / 45h/epoch）线性外推会是**数周级**，不划算。
