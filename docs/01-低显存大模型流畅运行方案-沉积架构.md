# 「沉积」（Sediment-LLM）：面向小显存设备的双向流动推理架构方案

> 引子：本方案以《低显存LLM插件化架构可行性评估报告》（2026-07-31）为地基。该报告已证明"常驻骨干 + 按需插件"在弱版本下可行（R 方案，prompt 级加载），并指出了四个尚未被占领的留白：中粒度插件带（E.2）、寻址 ABI / 可回写技能 / 生成式插件（E.3）。本方案不在已证可行的轨道上重复，而是把这四个留白合并成一个新机制——**把显存从"静态容器"改造成"随使用自组织演化的沉积盆地"**。
>
> 硬件锚点沿用报告：6 GB VRAM（RTX 4050 Laptop）+ 32 GB RAM + NVMe。结论可外推到 4–12 GB 档。
> 标注约定：〔推算〕= 基于带宽模型的估计，需实测；〔已证〕= 报告已给出系统证据。

---

## 1. 核心洞察：所有现有方案都是"单向"的

把报告梳理过的全部系统排成一个方向轴：

| 系统 | 流动方向 | 显存的角色 |
|---|---|---|
| KTransformers / llama.cpp 专家卸载 | 无流动（冷专家永驻 DRAM 就地算） | 静态 |
| S-LoRA / RAMoLE / llama.cpp `--lora` | **库 → 显存**（加载） | 静态容器 + LRU |
| PowerInfer | 常驻 + 外置，按激活读写 | 半静态 |
| RAG | 库 → prompt | 不涉及权重 |

**共同盲区：没有一个方案存在"显存 → 库"的上行沉淀路径，也没有方案让显存内容随使用频率自动重组。** 用户买一块 6 GB 卡，第一天的表现和第一百天的表现完全一样——插件系统是"仓库+吊装"，不是"生态"。

本方案的立论一句话：

> **让小显存流畅跑大能力，缺的不是更快的搬运（加载优化已逼近物理上限〔已证〕），而是让正确的参数在正确的时间自己待在正确的层级——需要给插件系统装上"时间"和"梯度"两个被忽略的自由维度。**

由此得到架构的两大支柱：**分频沉积（垂直方向，双向流动）** 与 **统一驻留仲裁（水平方向，KV 与插件同池竞价）**。

## 2. 支柱一：分频沉积——五层带 + 双向流动

### 2.1 五层驻留带（自上而下，频率递减）

报告的 C.5 给出"最优载体 = f(使用频率)"的分频原理，但只落到三层（骨干权重 / 适配器 / 检索）。本方案细化为五层带，并**为层间流动定义自动化机制**：

```
L0 岩基带（常驻显存，永不流动）
   混合骨干：4B 级稠密（attention + 路由 + 常识）Q4_K_M ≈ 2.2–2.8 GB〔已证预算〕
   + 短程神经记忆读出头（见 2.3，< 0.2 GB）
L1 热沉积带（常驻显存，由使用自动生成）           ← 本方案新增层
   高频技能/知识的"蒸馏沉积物"：若干 r=8 小 LoRA + 压缩记忆槽
   预算 0.8–1.2 GB，内容由沉积算法自组织，不由人摆放
L2 会话带（显存↔钉选内存，turn 级流动）
   当前激活的任务插件（LoRA / 中粒度模块）≤ 0.5 GB〔已证：R 方案舒适区〕
L3 频带库（钉选内存，请求级流动）
   冷插件池 20–30 GB + 记忆状态包仓库〔已证：报告 6.1〕
L4 潜码带（NVMe，近乎零体积）                      ← 本方案新增层
   极低频技能的"基因"：超网络潜码（每个几 KB）而非权重文件（每个几百 MB）
```

### 2.2 上行路径：沉积（Sediment）——方案的第一个创新点

现有系统只有"加载"；本方案加入**由使用频率驱动的上行流动**，三条通道：

**通道 1：使用即回写（可回写插件，报告 E.3.2 的产品化）**
- L2/L3 的插件内部维持一个小型**快权重关联记忆**（低秩 key-value 矩阵，Titans 谱系〔研究前沿，需自验证〕）；
- 会话中新学到的稳定模式（用户纠正、反复使用的格式、域内固定搭配）以低秩增量形式写入插件的快权重层，而不是留在 prompt 里；
- 会话结束：快权重增量随插件一起降回 L3 保存。**技能真的"越用越熟"**——这是 Transformer+LoRA 静态挂载形态做不到的，报告 F.3 已指出这是递归/快权重架构族的原生能力。

**通道 2：热蒸馏（L2/L3 → L1）**
- 调度器持续统计每个插件/记忆槽的"字节-频率分"：`score = 近 7 日激活 token 占比 × 质量增益估计 / 体积`；
- score 超阈值的插件，触发离线蒸馏：把该插件的效果压缩进一个 r=8 迷你 LoRA + 若干量化记忆槽（合计 ≤ 50–100 MB），晋升常驻 L1；
- 蒸馏在设备空闲时跑（充电+闲置检测），一次约几分钟〔推算，需实测〕；失败或质量回归不达标则放弃晋升，原插件继续走 L2 加载路径。
- **效果：用户使用越久，6 GB 显存里沉积出的"这台设备自己的模型"越贴合其真实工作负载——TTFT 里的加载税随时间自然消失。** 这是给插件系统装上"时间维度"的直接收益。

**通道 3：基因化（L3 → L4）**
- score 长期垫底的插件不删除，而是"降级为基因"：用超网络反演（或对潜码库做最近匹配）把其权重压成一个几 KB 的潜码，从磁盘腾身；
- 重新需要时由 2.4 的生成路径复原。质量有损〔推算〕，故只对"低频且质量不敏感"的长尾技能启用，且保留原文件指纹供强制回读。

**下行路径（风化 Weathering）**：L1 沉积物按 score 半衰期自动风化回 L3。L1 总预算硬顶，新晋升必挤走最冷旧沉积——带内永远是这台设备的"真实使用分布"，而非出厂配置。

### 2.3 记忆状态包与"寻址 ABI 的最小可行版"——第二个创新点

报告 E.3.1 说全行业缺件是"让第三方无需共训即可注入知识的标准格式"。本方案不试图一步到位定义完整 ABI，而是给出**可先落地的子集：MSP（Memory State Packet）格式**。

- **不打包权重切片，打包"状态"**：MSP = 低秩关联记忆（固定 M 个槽 × 固定 d 维 + 固定寻址度量 = 余弦 + 固定量化规格 Q8）+ 一个轻量**读出头**（~10 MB MLP）+ 元数据清单（基座指纹、槽使用率、冲突声明）。同族任何骨干 restore = 矩阵拷贝 + 读出头挂接，形状标准化使跨模型迁移有物理基础〔研究假设，见第 7 节实验 3〕。
- **缓解共训锁定的关键手法——"对分编译"类比**：知识方训练时不面向某个具体骨干，而是面向一份公开冻结的**参考骨干**（reference substrate，由社区固定版本、发布权重指纹）训练记忆包，就像编译器面向 ISA 而非某块 CPU。第三方与使用端之间只约定 ISA（MSP 格式），不约定实现。骨干换代时，由参考协议规定的"转译期"工具对新旧参考骨干做 MSP 重标定（只动读出头、不动槽内容）。这是把"共训锁定"从不可解的理论死结降级为可运维的版本管理成本〔架构主张，需实验检验〕。
- **接入带宽核算**：MSP 逐 token 读取按 2 MB/token 跨层计〔报告 C.1 给出该量级可行〕，走 DRAM→GPU 为轻载；且 L1 沉积机制保证高频槽位已本地化，实际跨层流量更低。

### 2.4 生成式插件——第三个创新点（报告 E.3.3 的系统化组合）

- 常驻一个 **60–100 MB 超网络**（放 CPU 侧钉选内存，用核显空闲算力或 GPU 流式执行〔推算〕），输入 = prompt 嵌入 + 会话摘要，输出 = r=8 LoRA 参数（~30–60 MB）；
- 长尾技能不再存文件、不再下载、不再走 NVMe→PCIe 搬几百 MB——**L4 只存几 KB 潜码，需要时现生成**。插件"库容"问题坍缩为"码本"问题；分发问题坍缩为发一个 code id；
- 生成耗时与 prefill 并行，隐藏进 TTFT〔与报告 D.4 的重叠原理相同，但把加载换成生成，链路更短〕；
- 与 MSP 互补：技能类（格式、风格、流程）走生成；知识类（事实域）走 MSP/检索。路由器的分工即"分频 × 分形"二维决策。

## 3. 支柱二：统一驻留仲裁——中粒度带的调度留白（报告 E.2）

报告指出 0.5–2 GB 中粒度模块与 KV cache 增长互斥，需要"插件驻留与 KV 驻留的联合调度策略"，此格子无人占领。本方案把它做成**显存内的市场机制**：

- 显存运行区只剩两个池：**L0+L1 固定区**（启动时锁定）与**竞价区**（剩余 ~2.5–3 GB，〔推算，依 6GB 预算表〕）；
- 竞价区里所有租户（KV 页 × N、激活插件 × K、超网络工作区）按**每字节边际价值**报价：
  - KV 页报价 = 该页对生成质量的注意力贡献估计（PowerInfer 式激活统计的 KV 版〔推算〕）；
  - 插件报价 = 剩余会话预期质量增益 / 已占字节；
- 调度器周期仲裁：报价低者被驱逐（KV→CPU 卸载 / 插件→降回 L3）。典型相变：加载 300 MB 医疗模块 → 自动把上下文压成 Q8 KV 并卸载旧轮 KV，而不是 OOM；
- **护栏 = 报告 D.8 实验 2 的相图**：方案落地前先用"尺寸 × 上下文"扫描标定悬崖位置，把仲裁参数钉在相图安全侧；每个插件准入时携带"预算表标注"（每 token 跨层字节成本 × 命中率），满足 `Σ 成本 ≤ 带宽预算` 才上架〔报告 6.2.4 的护栏，本方案将其扩展为运行时动态竞价而非静态过滤〕。

## 4. 6 GB 卡的端到端形态（示例核算）

| 时点 | 显存内容 | 占用〔推算〕 |
|---|---|---|
| 空闲 | L0 骨干 2.6 + 超网络工作区 0.15 + L1 沉积 1.0 + 池底 | ≈ 4.0 GB，余 2 GB |
| 提示词到达 t0 | + 路由决策（嵌入检索，10–50 ms〔已证〕） | — |
| t1 加载窗口 | L2 插件 300 MB H2D（与 prefill 并行；若命中 L4 则超网络生成 30–60 MB 参数，无文件 I/O） | 峰值 ≤ 4.8 GB |
| t2–t3 生成 | KV 在竞价区内分页生长；快权重在线回写发生 | 解码 ≈ 15–25 tok/s（4B 骨干 + 稀疏读取 MSP 槽的折损〔推算〕） |
| t4 会话结束 | 插件带回写增量降回 L3；L2 卸载；L1 候选进入蒸馏队列 | 回到空闲态 |

与报告结论的可信衔接：骨干尺寸、KV 量化、prompt 级加载、prefill 重叠全部沿用〔已证〕项；新增的不确定性集中在蒸馏质量保持、MSP 跨骨干迁移、超网络生成保真三处——即第 7 节实验要回答的三件事。

## 5. 创新点自检（对照报告 E 节的分层判定框架）

| 层 | 报告已认定的留白 | 本方案的推进 | 诚实定位 |
|---|---|---|---|
| 科学原理 | E.3 三个开放问题各自孤立 | **合并为"双向流动 + 分频五带"一个机制**：沉积/风化是别人没提的第四维（时间）；ISA 化 MSP 把"寻址 ABI"从理论问题降为版本管理问题 | 新机制主张，但建立在 Titans/快权重〔研究前沿〕之上，非凭空 |
| 系统集成 | E.2 中粒度带无人做 | 竞价式统一驻留仲裁（市场机制），比"策略性驱逐"更进一步 | 系统创新，可证伪（相图对比） |
| 产品生态 | "消费者 Windows 6GB 上的事实标准"无人完成 | L4 基因库使"技能市场"的分发体积从百 MB 降到 KB；沉积带使每台设备模型个性化 | 先手机会，非研究级 |

一句话：**报告说"真正配得上创新的是寻址 ABI、可回写技能、生成式插件"——本方案把三者焊成一条"使用频率驱动的双向流水线"，并为最难的寻址 ABI 给出可落地的最小版本（MSP + 参考骨干 ISA 化）。**

## 6. 风险映射（对照报告 §4 增量部分）

| 风险 | 内容 | 处置 |
|---|---|---|
| N1 蒸馏降智 | 热沉积的迷你 LoRA 可能保不住原插件行为 | 晋升前置任务级评测门（报告 6.2.6 的验收协议复用）；不达标不进 L1 |
| N2 快权重不稳定 | 在线回写可能漂移、污染技能 | 增量写与原始权重分文件存、可 diff 可回滚；限制单会话写容量 |
| N3 MSP 迁移失败 | 共训锁定没有真正被 ISA 化缓解 | 即第 7 节实验 3，失败则 MSP 退化为"同骨干版本管理格式"，方案主体不受损 |
| N4 调度器自身毛刺 | 竞价仲裁引入新决策环 | 仲裁周期 ≥ 1 s、动作限幅；驱逐决策全部可观测日志化 |
| N5 超网络过拟合码本 | 生成的参数只像"平均技能"不像具体插件 | L4 仅作降级路径，原文件仍是真理源 |
| 报告原风险 | R3/R4/R5/R8 | 全部沿用其缓解措施（会话亲和、MoLE 式组合、双缓冲、safetensors+签名） |

## 7. 验证路线（在报告 6.4 的 6–8 周之上做增量）

1. **W1–2**：复现报告基线（4B-Q4 + LoRA 切换 + 相图扫描）——确认地基数字；
2. **W3–4 · 实验 1（沉积闭环）**：跑双域负载 200 轮，验证"使用统计 → 蒸馏 → L1 晋升 → 回归测试"全链路，指标：晋升插件在 L1 常驻后的任务分保持率 ≥ 95%？TTFT 随使用轮数的下降曲线；
3. **W4–5 · 实验 2（生成式插件）**：用 LoRA 自编码器类方法训超网络，指标：生成参数 vs 原文件的任务分差、生成耗时是否 < prefill 时长；
4. **W5–7 · 实验 3（MSP 迁移，存亡假设）**：玩具规模（0.5–1B）双骨干，冻结骨干 B，面向参考骨干 A 训记忆包，插入 B 跑域内 QA——对应报告 F.4.4 的存亡检验；(b) ≥ 95%×(a) 则"寻址 ABI 可 ISA 化"升格，否则诚实收缩为同骨干格式标准；
5. **W7–8**：竞价仲裁器上线压测 + 出具 6 GB 档护栏配置与整机评测报告。

判定规则前置：实验 3 失败不影响方案交付形态（退化为 L0–L2 + 生成式长尾），只是生态故事从"跨模型知识包市场"收缩为"同族技能成长"。

## 8. 结语

报告教会我们的最重要一课是：**换页粒度决定系统生死**（虚拟内存史的教训在 LLM 上重演）。本方案把这一课推向下一步——虚拟内存真正强大不是因为页表，而是因为**工作集原理**：让"最近常用的"自动留在最快的层级。沉积架构就是给低显存推理装上工作集机制：向下用带宽数学守住流畅底线〔已证〕，向上用时间维度让 6 GB 卡长出"这台机器自己的模型"。小显存跑得流畅是工程问题，已被解决；跑得**越用越好**，是本方案主张的新问题。
