## 摘要（Executive Summary）

小显存设备（6–8GB 消费级/老笔记本 GPU）运行"大一点"的模型，现有主流路线是把参数放到内存甚至磁盘上按需搬运（offload / 流式加载 / LoRA 热切换）。本报告解释的「沉积架构」提出了一个不同的基本视角：

**搬运本身不是待优化的成本，而是待消除的结构——只要让驻留层级随使用统计"自己长出来"。**

一句话立论：所有现存低显存方案都只做"存储 → 显存"的**单向加载**；给这套系统补上缺失的两个维度——**时间**（使用统计驱动驻留演化）与**梯度**（驻留的技能可被在线精炼与蒸馏晋升）——显存就从"被动的容器"变成"随使用自组织演化的沉积盆地"，用得越久，搬运越少，且设备上会长出一个"只属于这台机器的模型"。

围绕这一立论，方案定义了三个核心机制，本报告的实验部分用**两级独立实现**（Node 代理尺度 + PyTorch 真实训练）对其做了可证伪检验，主要结论：

| 机制主张 | 代理尺度 | 真实模型尺度 | 裁决 |
|---|---|---|---|
| 分频沉积：技能按使用自动晋升常驻、加载税随使用衰减 | 税 p95 −84.6% | 税 p95 145→30ms，命中率 0.74→0.96，任务分不降反升 | **成立〔实测〕** |
| MSP 跨骨干寻址 ABI（记忆包"面向参考骨干发布、任意骨干读回"） | 达联合上限 91.5% | 达上限 94%（不转译=0%） | **部分成立，差 95% 线一步〔实测〕** |
| L4 基因化（技能参数压缩成 KB 级潜码） | 参数余弦判失败 | 行为保真可达（K≥5 时 0.98–1.02）但**磁盘零收益** | **PCA 路线不成立，必须真超网络〔实测〕** |
| 多 LoRA 加法联合合并常驻 | —（未测） | 保真 0.13–0.57，显著干扰 | **证伪；政策改为隔离挂载〔实测〕** |
| 统一驻留仲裁填补"中粒度插件带" | 相图通过率 11/28→22/28 | —（机制层，无需真模型） | **成立（代理尺度）〔实测〕** |

最有价值的产出不是 5 项中的 3 项通过，而是 2 项**被设计好的实验诚实地杀死了方案自己的分支**（融合蒸馏、PCA 基因化）——这正是"可证伪设计"的目的：用最小代价划出方案里哪些部分是真的、哪些需要在真实规模上重新出发。

## 1. 问题本源：为什么"加载税"在低显存上是结构性的

### 1.1 三条物理地板〔推算，锚定源报告 §2.1 带宽表〕

Node 原型 E-band 实验独立复算了源报告的三条推论，全部在 ±5% 内对齐：

```
推论1  稠密 7–8B Q4 逐 token 过 PCIe(x16 25GB/s)： 5.68 tok/s（报告 5.7）
       同一模型过 x8 笔记本链路(10GB/s 保守端)：   2.27 tok/s（报告：跌到 2 tok/s 级）
       NVMe→DRAM→VRAM 三级串联流式：              0.91 tok/s（灾难区确认）
推论2  MoE 激活专家 DRAM 带宽下限：                ≥4.0 tok/s（报告实测 8.7–13.7，AMX 路径高于下限）
推论3  300MB LoRA 摊薄到 4096 token：             0.073 MB/token（无感）
       300MB 冷加载一次（NVMe+H2D+挂载）：         96.6 ms（百 ms 级）
综合    2.6GB 常驻 + 2MB/token 外置读的解码上限：   22.0 tok/s（报告 §6.3 实测 20–30 区间内）
```

这些数字给出两个关键判断：

- **地板是带宽乘除法的直接结果，不是工程没做好。** 逐 token 流式加载参数在笔记本链路上必然掉到 2 tok/s 级——这条路不是"优化后可救"，是算术上死了。
- **但"按请求加载整个插件"是另一回事。** 96.6ms 的冷加载摊到一次 4096-token 生成上只有 0.073 MB/token——**加载贵不在带宽，贵在每个请求都要交一次"搬运税"**（百 ms 级 TTFT 抖动），且与长上下文争抢同一块显存。

### 1.2 从"优化搬运"到"消除搬运"的视角翻转

主流方案（llama.cpp mmap、ktransformers、S-LoRA 等）都在优化"每一次搬运"：异步预取、分层 pin、批量挂载。搬运优化的极限就是把 96.6ms 压到 60ms、把抖动做平滑——**结构不变，税永远在**。

沉积架构的问题是：**什么情况下这个税可以归零？** 答案是显然但被忽略的：当被搬运的对象**恰好在显存里已经有位置**的时候。于是真正的问题从"搬得快"变成"什么该常驻"——而"什么该常驻"恰恰是一个**只能在使用中获得的统计量**。这就是"时间维度"的入口：驻留决策不是加载时刻的一次性判断（LRU 只看过去命中），而是一个持续学习的过程。

## 2. 方案核心：三个机制的解释

### 2.1 分频沉积：五层驻留带与双向流动

类比地质沉积：粗重颗粒先沉、细沙后沉、悬浮物留在上层——不同"频率"的成分自动进入不同层级。系统的显存/内存/磁盘不再是"缓存的三层"，而是**语义分层**的五带：

```
L0 岩基带   常驻显存   骨干模型权重本体（永远不动）
L1 热沉积带 常驻显存   高频技能经"热蒸馏"晋升后的产物——自组织、可增可减
L2 会话带   显存↔钉选内存  当前会话激活的插件（搬运发生在这里）
L3 频带库   钉选内存   中低频技能全集（秒级可上显存）
L4 潜码带   NVMe      低频技能的 KB 级"基因"（潜码，非参数文件）
```

关键与单向加载范式的区别有三：

1. **方向是双向的。** 技能不仅"需要时从磁盘搬上来"，还会沿 L4→L3→L2→L1 **自发晋升**——触发条件是实测的使用分数（频次×新近度加权）超过阈值，且蒸馏保真通过验收门；反向的"风化"（L1→L3 降级、L3→L4 基因化）同样自发。
2. **晋升的产物不是原件的拷贝，是蒸馏物。** L1 常驻的不是原 LoRA 文件，而是从使用数据中"再训练"出的更紧凑表示——这保证常驻预算内能装下最多有效技能。
3. **驻留带会随设备的使用历史而不同。** 两台同型号 6GB 显卡的机器，沉积出一对不同的 L1——这就是"这台机器自己的模型"的来源。

**热沉积为什么必须是"行为蒸馏"而不是"参数截断"？** 方案原本假设可以用 SVD 把 LoRA ΔW 截到更低秩来省预算。实验给出了一条清晰的证据链（见 §5.2–5.3）：截断是否可行**取决于技能间干扰度**——技能作用于互斥的 token 区间时 rank8 截断保真 ≥0.966；技能共享输入区时同一操作跌到 0.75–0.85。而"多个技能融合成一个超级技能"的路线（一次训练拟合多个教师）在真实模型上彻底失败（0.23–0.80，秩扩到 48 也不够）。结论：**L1 的合法产物是"单技能蒸馏/截断"，跨技能融合被否**。这是玩具尺度下就抓到的结构性质，不需要等真实大模型来纠正。

### 2.2 MSP 记忆状态包：把"寻址 ABI"降维成格式标准

源报告认为跨模型共享知识"理论上死结"——模型 A 的知识编码在 A 的坐标里，B 读不懂；要对齐需要共同训练。方案把这个问题**从表示学习降维到格式约定**，类比是编译器的 ISA：

> 编译器不要求两个 CPU 内部相同，只要求二进制面向一个公开的、冻结的指令集 ABI 生成。
> 同理：记忆包面向"参考骨干的表示空间"训练，任意目标骨干凭一份**锚点标定**读回。

MSP 的构成：固定槽数 × key/value（参考骨干坐标，Q8 量化）+ 读出头 + 元数据。目标骨干使用时只做一件事：拿几十个公开锚点文本，分别过参考骨干和本地骨干，收集两侧 hidden 表示，**拟合一个线性探针**（本地→参考），然后把记忆包的键空间标定过来。这一步不需要梯度、不需要重训、不触碰本地权重。

这为什么可能成立？依据是表示学习里反复观察到的现象：同架构、同任务的不同训练模型的内部表示之间，存在大体**线性可译**的对应关系（representation alignment 文献的主流结论）。MSP 赌的就是"线性探针足够吃掉大部分差异"。实验 3 正是在真实模型上量测这个赌注的赔率（§5.4）。

### 2.3 统一驻留仲裁：显存剩余区当作竞价市场

源报告 §E.2 指出一个无人占领的留白：细粒度（逐权重流）与粗粒度（整文件加载）之间存在**中粒度插件带**，但没人回答"大插件与长上下文 KV 在 6GB 上怎么共处"。方案的答案是不再区分两种东西的管理机制——显存扣除 L0/L1 固定区后的运行区做成**拍卖市场**：

- 租户 = KV 页 与 激活插件，各带一个边际价值报价（KV 页按注意力贡献×新近度衰减；插件按剩余会话预期增益/字节）；
- 周期结算，低报价者驱逐出显存（KV→钉选内存，插件→L3）；
- 每周期动作限幅（驱逐 1 名），避免震荡。

这是一个纯机制层设计，不需要真 GPU 也能验证其不变量（无 OOM、命中率、收敛性）——Node 原型直接实测了它把"插件尺寸×上下文"相图的通过率从 11/28 提到 22/28（§5.5）。

## 3. 为什么做两级原型：实验设计哲学

方案 §7 定义了 4 组可证伪实验。直接跳到 llama.cpp + 真实 7B 的验证成本高一个数量级；纯数学推导又容易自欺。因此采用**双尺度互证**：

- **第一级（Node.js 代理原型）**：零依赖纯 JS（自带矩阵/岭回归/PCA/量化），模型质量用"能力向量余弦"代理，但调度器、带账本、MSP 转译、竞价仲裁、带宽数学**全部真实计算**。目的：廉价检验**系统层动力学**（几千行决策逻辑里有没有写反的地方）。
- **第二级（PyTorch 真实训练）**：借用户本机训练环境（Python 3.13 + torch 2.11 + CUDA，2×RTX 2080 Ti），真实训练 d=96 两层 Transformer 骨干 + 6 个 LoRA 技能，评测用真实 next-token 精度，权重操作（合并/还原/序列化/读回）都是真张量写回。目的：剥离"代理指标是否自欺"的风险，检验**同一批主张在真梯度、真参数空间里是否依然成立**。

两级用的是**不同的数值实现、不同的指标定义**，所以结论同向时才有意义。这一点确实产生了价值：E2 基因化在 Node 级按"参数余弦"判了失败，真实级按"行为保真"重测后翻案（可达 0.98+），但随即暴露出更致命的新问题（零压缩）——单一尺度任何一级都会给出误导性的半截结论。

## 4. 实现解释：代码怎么对应方案

### 4.1 Node 原型（`sediment-llm/`，9 个模块）

```
m0-linalg.js   线性代数核心：矩阵乘、岭回归、最小二乘、PCA(幂迭代)、Q8 量化
m1-hw.js       带宽模型：token 流上限、prefill/解码、冷加载分段计时（报告 §2.1 锚定）
m2-bands.js    L0–L4 五带账本 + 晋升/风化/基因化动作 + 使用分数
m3-msp.js      记忆包训练（真实梯度）、量化序列化/读回、参考→目标探针转译
m4-gene.js     LoRA 家族 → 共享码本 → K 维潜码 → 重建保真扫描
m5-arbiter.js  竞价仲裁器 + 一次请求的端到端时序分解（TTFT/峰值/解码）

运行方式：`node src/index.js all`（本机无 Python 时的第一实现，纯 JS 零依赖）。

```

**语料设计的两次教训**（都进了注释与结果）：v1 让各技能链共享输入 token 区间 → 同一前缀有多个"正确"后继，教师在冲突标签上监督学生，蒸馏与评测全被污染；v2 改为**每链绑定互斥 token 区间**（技能近正交），一切才变得可解释。这说明玩具域实验最大的坑不是规模，而是**任务域的良定义性**——真实语言域天然带干扰谱，外推时须按 §5.2 的干扰敏感度理解。

### 4.3 诚实边界（未实现/不可外推项）

1. **玩具规模**：d=96、马尔可夫语料——验证的是机制动力学与决策正确性，**所有绝对 MB/ms/精度数字不外推**到 7B；6GB 笔记本档的物理账走 m1/hw.py 的报告锚定参数，本机 2080 Ti 仅承担"真实训练"角色。
2. **快权重在线回写（L1"越用越熟"通道）未实现**——需要更长训练周期与遗忘防护设计，列入下一阶段。
3. **E3 的知识域是单 token 置换**，键空间判别性远强于自然语言；真实场景 b/a 比例预期低于 94%，这是推向真实模型必须重测的头号量。
4. MSP 槽 Python 版为 fp32（442KB）；Q8 量化在 Node 版已实现，两版结合即完整格式。

## 5. 实验结果全解读〔实测〕

### 5.0 地基校准：本机实测 vs 模型假设

`bench_io.py` 实测 H2D pinned = **11.3 GB/s**（模型采用的 x8 保守假设 12 GB/s，偏差 <6%）；本机 VRAM 读写 ≈500 GB/s（2080 Ti 档；6GB 笔记本档模型假设 90 GB/s）。→ 带宽数学模型无需修正。

### 5.1 E-band / E4（Node）：报告复算与仲裁相图

- 三条推论复算全部对齐（§1.1 表）。
- 端到端一次请求时序：空闲态 TTFT 350ms、300MB 冷插件 670ms（加载被 prefill 隐藏后用户无感）、300MB 热插件 1310ms、解码均 ≈22 tok/s；**2GB"大脑插件"正确触发峰值 6676MB > 6144MB 判 OOM**——方案 D.6"插件不消除峰值约束"的预期被实算复现。
- 竞价仲裁：静态（无仲裁）相图通过 11/28 → 仲裁后 **22/28**，中粒度插件带在 6GB 档从"多数组合 OOM"变为"可运营"。

### 5.2 E1c/E1d（真实）：沉积闭环成立，且条件清晰

```
E1d 旗舰：rank8 SVD 蒸馏 → 真实保真 {链2:1.007, 链3:0.972, 链4:1.001, 链5:0.995} ≥ 门 0.95 → 晋升
         3 槽 L1 由使用分数换入换出（终态 {2,4,3}）；隔离挂载=真实权重写回，0.17ms（玩具尺寸）
         200 轮 Zipf：常驻命中率 0.74→0.96；加载税 p95 145→30ms；任务分 0.262→0.282（不降反升）
E1c 消融：区间互斥语料下 rank6–16 保真全线 ≥0.966（rank16=原秩，无损）
         对照 v1 共享区间语料：rank8 保真仅 0.75–0.85 → 门正确拒绝（护栏双向验证）
```

解释：**晋升机制在真实参数空间上工作正常，且保真门同时表现出"放行合法候选"与"拦截劣质候选"两种正确行为**。E1c 的对照给出了方案需要的一个精确化修正：热沉积的可行性前提不是"低秩"，而是"技能间干扰度低"——真实技能的干扰谱应在下一阶段用真实语料量测。

### 5.3 E1b（真实）：融合超级技能被否——负结果的机制原因

一个学生 LoRA 同时拟合 4 个教师：rank16 保真 0.23–0.62；补救到 rank48 + 温度 KD 仍 0.41–0.80，全部低于 0.95 门被拒。机制解释：4 条链各需约 rank8 的独立子空间，并集需要 ≈rank32 的**同时可用**容量，而低秩因式分解的 A·B 乘积结构使子空间无法正交排布——秩并集直觉在乘积参数化下不成立。**判决：L1 不做跨技能融合，保持"每技能一蒸馏体"。**

### 5.4 E2（真实）：基因化的"翻案与再失败"

```
B 组 PCA 基因化：K=2–4 行为保真 0.19–0.87（不可用）；K=5–6 达 0.98–1.02（可用！）
  → Node 级"参数余弦判失败"在行为层面翻案：低秩重建"不像原件"不等于"不能用"
致命伤：raw_kb 648 → latent+codebook 648——码本本身含全部方差，共享 PCA 路线磁盘零收益
A 组 联合合并复测：6 技能 ΔW 直接相加常驻 → 保真 {0.153, 0.573, 0.356, 0.379, 0.126, 0.424}
  → 报告 R4（负迁移）风险拿到直接数字；即使区间互斥域仍显著干扰 → 必须隔离挂载（E1d 政策）
```

判决：方案 §2.4 的"L4 潜码带"作为**存储格式**没有意义（省不了空间），但作为**检索索引**（潜码→相似技能命中→再取原件）价值保留；参数生成路线必须换成真超网络（prompt→参数），这是本实验组合烧出来的最贵也最清楚的一张地图。

### 5.5 E3（真实）：存亡假设检验——ISA 转译 94%

知识域=骨干未见过的 50 对 (cue→answer) 秘密置换（骨干裸答 0.02=随机水平，证明知识确属外挂）；四臂全部真实 token 精度：

```
oracle 容量（one-hot 键）          1.00  ← 记忆包本身够用，排除"容量不足"混淆
(a) 联合上限（键=目标骨干原生坐标）  1.00
(b) ISA 转译（面向参考骨干发布→序列化→读回→60 锚点线性标定） 0.94
(b0) 不转译直读                     0.00  ← 坐标错配=完全失效，证明转译确在工作
锚点漂移曲线：4→0.10, 8→0.18, 16→0.36, 32→0.64, 48→0.96 → 单调收敛，标定成本可预期
probe 相对误差 0.019 —— 线性近似本身已很准
```

判决：**b/a = 94%，显著优于随机但未过 95% 预注册线 → "部分成立"**。剩余 6% 差距的来源被精确定位为骨干间非线性残余（探针误差 0.019 说明线性项几乎吃尽）。可行的补法：非线性标定（多层探针）或把锚点需求作为 ABI 文档的一部分发布（60 锚点→0.94 是玩具尺度，真实模型锚点集成本按比例核算）。两级尺度互证：Node 91.5% / 真实 94%，同落在 90–95% 带——**跨骨干知识共享从"理论死结"降格为"标定工程问题"这一步，得到了真实模型证据**。

## 6. 讨论：这一轮证据把方案改成了什么样

实验不是给方案"盖章"，而是真正修改了方案的四个部件（以下已回写进方案认知）：

1. **L1 晋升产物规格收窄**：从"蒸馏任意粒度"收窄为"单技能截断/蒸馏，禁融合"（E1b 证据）。
2. **干扰度成为一等公民参数**：晋升门之外新增"技能区间重叠度"前置检查（E1c 的 v1/v2 对照）——这是真实域部署前必须量测的量。
3. **L4 定位重写**：从"压缩存储"改为"检索索引 + 原件兜底"，真超网络列为独立研究项而非实现细节（E2 证据）。
4. **挂载政策改判**：多技能并存一律隔离挂载（merge→评→restore 循环），禁止算术合并常驻（E2-A 证据，代价是常驻技能各占 L1 槽位，与 §5.2 的预算机制自然衔接）。

同时，方案的三根主梁——双向流动消除搬运税、寻址 ABI 使跨骨干共享从不可能变为标定问题、竞价仲裁使中粒度带可运营——全部拿到了两级独立证据支持。立论没有被推翻，被推翻的都是我们自己加的乐观分支，这正是可证伪设计应有的形状。

## 7. 局限与下一步

**局限**（全部明示）：玩具模型规模；马尔可夫语料与自然语言的干扰谱差异；快权重回写通道未实现；6GB 档物理账是锚定推算而非该档硬件实测；仲裁报价函数是设计选择而非最优解证明。

**下一步路线**（按依赖序）：

1. **规模升级**：0.5–1B 真实小模型（Pythia/Qwen-0.5B）+ 自然语言技能域，重跑 E1d/E2/E3——头号输出量：真实语言域 b/a 比例与技能干扰谱；
2. **MSP 格式冻结**：Q8 槽（Node 版）×  fp32 训练（PyTorch 版）合并成可发布的 v0.1 格式 + 锚点集规范，先在真实模型对上把 b/a 推过 95%（候选：非线性探针、锚点加权）；
3. **真超网络试验**：L4 参数生成路线的可行性单点验证（决定 §2.4 存废）；
4. **快权重回写**：L1 常驻体在使用中的在线精炼 + 遗忘防护（方案的"越用越熟"主张目前仍未验证）；
5. **llama.cpp 集成原型**：把 m5 仲裁器接到真实推理引擎的 KV 页管理器上，用报告 §5.3 的 11 个真实负载跑端到端。
